## Backend API

Evaluation routes live in `llm_d_bench/evaluate/router.py` with the `/api/v1/evaluate` prefix. Request models are defined in `llm_d_bench.evaluate.models`; named HTTP response models are defined in `llm_d_bench.evaluate.api_models`.

Run, workflow, case, and detail responses preserve additional stored fields. Optional fields absent from the record remain omitted; explicitly stored `null` values remain `null`. List responses retain their `{ "items": [...] }` envelope. Python route functions return dictionaries; FastAPI applies the named response models at the HTTP boundary.

Errors use the application's `application/problem+json` response with `type`, `status`, `title`, `detail`, `code`, and an optional `requestId`. `detail` can contain structured validation errors. Authentication and resource permissions still apply; declaring a response model does not grant access.

### Get benchmark defaults

Get llm-d-benchmark default repository and runtime settings Lens Evaluate will use.

<Tabs>
  <Tab title="REST API">
    **`GET /api/v1/evaluate/benchmark-defaults`**

    Request: no body.

    Response: HTTP `200`, `BenchmarkDefaultsResponse`.

    ```json
    {
      "mode": "managed-source",
      "repository": "https://github.com/llm-d/llm-d-benchmark.git",
      "revision": "main",
      "localRuntimeConfigured": false
    }
    ```
  </Tab>
  <Tab title="Python API">

```python
import asyncio

from llm_d_bench.evaluate.router import benchmark_defaults


async def main() -> None:
    defaults = await benchmark_defaults()
    print(defaults["mode"], defaults["repository"], defaults["revision"])


asyncio.run(main())
```

### Start a benchmark run

Start a benchmark run against a ready deployment execution or a published Model Service.

<Tabs>
  <Tab title="REST API">
    **`POST /api/v1/evaluate/runs`**

    Request body: `EvaluateRunRequest`
    - `deployment_execution_id` (`string`, optional) — benchmark a specific deployment execution directly.
    - `model_service_group_id` (`string`, optional) — benchmark a published, continuously health-probed
      Model Service instead; the harness resolves it to the group's active member and published name and
      requires `api_key`. Exactly one of `deployment_execution_id` or `model_service_group_id` must be set.
    - `api_key` (`string`, optional) — model access token; required when `model_service_group_id` is set.
    - `cluster_session_id` (`string`, optional; must match the execution session when supplied)
    - `harness`, `workload`, `workload_yaml`, `parallelism`, `wait_timeout_seconds`, `harness_memory_gib`
    - `accelerator_profile`, `storage_class_name`, `matrix`, `concurrency_stages`, `warmup_requests`, `shared_prefix`
    - `sla_targets` (`BenchmarkSlaTargets`)
    - `specification_file`, `http_proxy`, `https_proxy`, `no_proxy`, `benchmark_source`, `use_baseline_endpoint`

### Delete a benchmark run

Delete a terminal standalone benchmark and its saved results.

<Tabs>
  <Tab title="REST API">
    **`DELETE /api/v1/evaluate/runs/{run_id}`**

    Request: no body.
    - Path parameter: `run_id` (`string`, required)

    Response: HTTP `204 No Content`. No JSON body is returned.
  </Tab>
  <Tab title="Python API">

```python
from llm_d_bench.evaluate.router import _delete_benchmark_history, _get

run_id = "7d698fda-8e2e-44b2-86aa-14d24098350d"
run = _get("benchmark", run_id)
if run is not None and run.get("status") in {"succeeded", "failed", "cancelled"}:
    _delete_benchmark_history(run_id)
```
  </Tab>

### Start a deployment-plus-benchmark workflow

Start a simple deployment-plus-benchmark workflow that first creates an optimized baseline deployment, then benchmarks it.

<Tabs>
  <Tab title="REST API">
    **`POST /api/v1/evaluate/workflow-runs`**

    Request body: `EvaluateWorkflowRequest`
    - `model` (`string`, required)
    - `cluster_session_id` (`string`, required)
    - `replicas`, `tensor_parallel_size`, `image`, `harness`, `workload`, `parallelism`

    ```json
    {
      "model": "Qwen/Qwen3-8B",
      "cluster_session_id": "123e4567-e89b-12d3-a456-426614174000",
      "replicas": 1,
      "tensor_parallel_size": 1,
      "image": "ghcr.io/llm-d/llm-d-xpu:v0.9.0",
      "harness": "inference-perf",
      "workload": "sanity_random.yaml",
      "parallelism": 1
    }
    ```

    Response: HTTP `202`, `EvaluationWorkflowResponse`.

    ```json
    {
      "kind": "workflow",
      "deployment_ownership": "evaluation",
      "id": "0e8dd5de-8a1c-4f96-9756-fd91c1da4faa",
      "status": "deploying",
      "created_at": "2026-09-23T09:18:24.287000Z",
      "deployment_run_id": "deployment-1",
      "cluster_id": "cluster-1",
      "owner_user_id": "user-1",
      "model": "Qwen/Qwen3-8B",
      "harness": "inference-perf",
      "workload": "sanity_random.yaml",
      "parallelism": 1,
      "benchmark_runtime": {}
    }
    ```
  </Tab>
  <Tab title="Python API">

```python
import asyncio

from llm_d_bench.evaluate.models import EvaluateWorkflowRequest
from llm_d_bench.evaluate.router import create_workflow_run


async def main() -> None:
    workflow = await create_workflow_run(
        EvaluateWorkflowRequest(
            model="Qwen/Qwen3-8B",
            cluster_session_id="123e4567-e89b-12d3-a456-426614174000",
            replicas=1,
            tensor_parallel_size=1,
            workload="sanity_random.yaml",
        )
    )
    print(workflow["id"], workflow["status"])


asyncio.run(main())
```

### Get detailed evaluation workflow results

Get expanded evaluation workflow results and deployment links.

For workflows with cases, the report uses `comparison_version: 2`. Older cached reports are regenerated from retained evidence when details are read. Matrix rows match unique successful `(isl, osl)` points and explicit `concurrency`; rate stages match explicit `rate`. Missing, non-finite, negative, or duplicate load keys do not establish a match, and array position is never a fallback. No matched rows means the corresponding statistics are `null`.

Ratios are guide divided by baseline. A valid zero numerator is retained, including in the geometric mean; a zero denominator yields no ratio. Suite-normalized throughput uses only matched pairs where both sides have nonnegative output-token counts and positive measured durations. Mean, P90, and P99 aggregates remain separate.
