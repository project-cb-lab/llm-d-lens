## Backend API

Observability is split across five FastAPI routers under `llm_d_bench/monitoring/`: `accelerator/router.py`, `cluster_stack/router.py`, `deployment/router.py`, `gpu_driver/router.py`, and `profiling/router.py`.

### List accelerator observability capabilities

List accelerator observability capabilities Lens supports, including access modes and default namespaces.

<Tabs>
  <Tab title="REST API">
    **`GET /api/v1/monitoring/accelerators`**

    Request: no request body.

    Response: returns an `AcceleratorCapabilitiesResponse` with supported accelerator families.

    ```json
    {
      "accelerators": [
        {
          "type": "intel_gpu",
          "display_name": "Intel GPU",
          "access_modes": ["dra", "plugin"],
          "release_name": "xpumd",
          "default_namespace": "intel-xpumd"
        },
        {
          "type": "nvidia_gpu",
          "display_name": "NVIDIA GPU",
          "access_modes": ["plugin", "dra"],
          "release_name": "dcgm-exporter",
          "default_namespace": "dcgm-exporter"
        }
      ]
    }
    ```
  </Tab>
  <Tab title="Python API">
    ```python
    from llm_d_bench.monitoring.accelerator.service import capabilities

    response = capabilities()
    print(response.model_dump())
    ```
  </Tab>
</Tabs>

### Get accelerator observability status

Get observability status for one accelerator family, including release, component, and access-mode health.

<Tabs>
  <Tab title="REST API">
    **`GET /api/v1/monitoring/accelerators/{accelerator}/status`**

    Request: no request body. Path param: `accelerator` (`str`, one of the registered families: `intel_gpu` or `nvidia_gpu`). Query params: `namespace` (`str`, default `intel-xpumd` for Intel, `dcgm-exporter` for NVIDIA), `access_mode` (`"dra" | "plugin"`, optional), and `cluster_id` (`str`, optional).

    Response: returns an `AcceleratorStatusResponse`.

    ```json
    {
      "accelerator": "intel_gpu",
      "access_mode": "dra",
      "access_modes": [
        {
          "mode": "dra",
          "available": true,
          "detected": true,
          "message": null
        },
        {
          "mode": "plugin",
          "available": false,
          "detected": false,
          "message": "device plugin not installed"
        }
      ],
      "cluster_reachable": true,
      "context": "kind-test",
      "namespace": "intel-xpumd",
      "release": {
        "name": "xpumd",
        "status": "deployed",
        "chart": "xpumd-0.1.0",
        "revision": 1
      },
      "status": "ready",
      "message": "ready",
      "components": [
        {
          "name": "xpumd-controller",
          "status": "ready",
          "kind": "workload",
          "ready": 1,
          "desired": 1,
          "source": "xpumd",
          "diagnostics": []
        }
      ],
      "active_operation_id": null,
      "observed_at": "2026-09-23T08:00:00Z",
      "stale": false
    }
    ```
  </Tab>
  <Tab title="Python API">
    ```python
    import asyncio

    from llm_d_bench.monitoring.accelerator.service import get_status, validate_namespace


    async def main() -> None:
        status = await get_status(
            "intel_gpu",
            validate_namespace("intel-xpumd"),
            "dra",
            cluster_id="cluster-123",
        )
        print(status.model_dump())


    asyncio.run(main())
    ```
  </Tab>
</Tabs>

### Install accelerator observability

Install accelerator observability components for a supported accelerator family.

<Tabs>
  <Tab title="REST API">
    **`POST /api/v1/monitoring/accelerators/{accelerator}/installations`**

    Request: path param `accelerator` (`str`). Optional header: `Idempotency-Key` (`str`). Optional query param: `cluster_id` (`str`). Body fields are `accelerator`, `access_mode`, and `namespace`.

    ```json
    {
      "accelerator": "intel_gpu",
      "access_mode": "dra",
      "namespace": "intel-xpumd"
    }
    ```

    Response: returns an `AcceleratorOperationResponse` for the queued install operation.

    ```json
    {
      "operation_id": "accel-op-123",
      "kind": "install",
      "status": "queued",
      "phase": "queued",
      "accelerator": "intel_gpu",
      "access_mode": "dra",
      "namespace": "intel-xpumd",
      "started_at": "2026-09-23T08:01:00Z",
      "finished_at": null,
      "exit_code": null,
      "logs": [],
      "error": null
    }
    ```
  </Tab>
  <Tab title="Python API">
    ```python
    import asyncio

    from llm_d_bench.monitoring.accelerator.models import AcceleratorInstallRequest
    from llm_d_bench.monitoring.accelerator.service import install


    async def main() -> None:
        operation = await install(
            AcceleratorInstallRequest(
                accelerator="intel_gpu",
                access_mode="dra",
                namespace="intel-xpumd",
            ),
            idempotency_key="request-123",
            cluster_id="cluster-123",
        )
        print(operation.model_dump())


    asyncio.run(main())
    ```
  </Tab>
</Tabs>

### Run cluster monitoring stack preflight

Run cluster monitoring stack preflight checks without installing anything. Use this before starting a Prometheus/Grafana stack installation.

<Tabs>
  <Tab title="REST API">
    **`POST /api/v1/monitoring/cluster-stack/installations/preflight`**

    Request: optional query param `cluster_id` (`str`). Body fields are `namespace`, `mode`, `enable_tls`, and `reinstall`.

    ```json
    {
      "namespace": "llm-d-monitoring",
      "mode": "central",
      "enable_tls": false,
      "reinstall": false
    }
    ```

    Response: returns a `ClusterStackPreflightResponse` with blocking and non-blocking checks.

    ```json
    {
      "allowed": true,
      "status": "ready",
      "checks": [
        {
          "name": "cluster-reachable",
          "passed": true,
          "message": "cluster is reachable",
          "blocking": true
        }
      ],
      "warnings": [],
      "command_preview": ["scripts/dev.sh", "monitoring-stack", "install"]
    }
    ```
  </Tab>
  <Tab title="Python API">
    ```python
    import asyncio

    from llm_d_bench.monitoring.cluster_stack.models import ClusterStackInstallRequest
    from llm_d_bench.monitoring.cluster_stack.service import preflight


    async def main() -> None:
        result = await preflight(
            ClusterStackInstallRequest(
                namespace="llm-d-monitoring",
                mode="central",
                enable_tls=False,
                reinstall=False,
            ),
            cluster_id="cluster-123",
        )
        print(result.model_dump())


    asyncio.run(main())
    ```
  </Tab>
</Tabs>

### Install cluster monitoring stack

Install or reinstall the cluster-level monitoring stack. Use this when Prometheus/Grafana cluster monitoring should be provisioned or repaired.

<Tabs>
  <Tab title="REST API">
    **`POST /api/v1/monitoring/cluster-stack/installations`**

    Request: optional header `Idempotency-Key` (`str`) and optional query param `cluster_id` (`str`). Body fields are `namespace`, `mode`, `enable_tls`, and `reinstall`.

    ```json
    {
      "namespace": "llm-d-monitoring",
      "mode": "central",
      "enable_tls": false,
      "reinstall": true
    }
    ```

    Response: returns a `ClusterStackOperationResponse` for the queued install or reinstall operation.

    ```json
    {
      "operation_id": "cluster-stack-op-123",
      "kind": "install",
      "status": "queued",
      "phase": "queued",
      "namespace": "llm-d-monitoring",
      "started_at": "2026-09-23T08:10:00Z",
      "finished_at": null,
      "exit_code": null,
      "logs": [],
      "error": null
    }
    ```
  </Tab>
  <Tab title="Python API">
    ```python
    import asyncio

    from llm_d_bench.monitoring.cluster_stack.models import ClusterStackInstallRequest
    from llm_d_bench.monitoring.cluster_stack.service import install


    async def main() -> None:
        operation = await install(
            ClusterStackInstallRequest(
                namespace="llm-d-monitoring",
                mode="central",
                enable_tls=False,
                reinstall=True,
    ```

### Manage deployment monitoring resources

Install, enable, disable, or uninstall monitoring resources for one deployment execution.

<Tabs>
  <Tab title="REST API">
    **`POST /api/v1/monitoring/deployments/{execution_id}/{action}`**

    Request: no request body. Path params: `execution_id` (`str`) and `action` (`str`, one of `install`, `enable`, `disable`, or `uninstall`). Optional query param: `cluster_id` (`str`).

    Response: returns the same deployment monitoring status shape after the requested action completes.

    ```json
    {
      "execution_id": "deploy-exec-001",
      "namespace": "llm-d-run-001",
      "cluster_reachable": true,
      "stack_ready": true,
      "status": "disabled",
      "enabled": false,
      "epp_service": {
        "name": "demo-epp",
        "labels": {
          "app.kubernetes.io/name": "demo-epp"
        },
        "service_account": "demo-epp"
      },
      "servicemonitors": [],
      "podmonitors": [],
      "message": "monitoring disabled"
    }
    ```
  </Tab>
  <Tab title="Python API">
    ```python
    import asyncio

    from llm_d_bench.monitoring.deployment.service import disable, enable, install, uninstall


    async def main() -> None:
        actions = {
            "install": install,
            "enable": enable,
            "disable": disable,
            "uninstall": uninstall,
        }
        result = await actions["disable"]("deploy-exec-001", "cluster-123")
        print(result)


    asyncio.run(main())
    ```
  </Tab>
</Tabs>

### Get GPU driver status

<Tabs>
  <Tab title="REST API">

    Response: returns a `GpuDriverStatusResponse`.

    ```json

      "ready": true,
      "cluster_reachable": true,
    ```

## Shared monitoring behavior

Monitoring services share command JSON parsing, Service link lookup, Prometheus query transport and operation runtime mechanics. Existing Python entry points and REST request/response contracts below are unchanged; domain errors, installer phases, DAO records and verification callbacks remain with their respective accelerator or cluster-stack service.
