Use the Model cache page to download models into registered cache storage, watch download progress, and clean up cached files. The steps below match the controls that exist in the current UI.

Changing cluster or search filters cancels superseded list requests. **Start download** prevents duplicate submissions and shows failures in the dialog for retry. Downloads continue to use the token saved with the selected cluster. **Rows per page** returns the list to the first page; the summary reflects the filtered cached models.

## How deployments use a cached model

When a deployment uses the **Shared Hugging Face cache first** model source with a ready cache, or the **Exact model folder** model source, its model server mounts the cache at `/model-cache` and starts with Hugging Face offline mode (`HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, plus `HF_HOME=/model-cache` for the shared cache). It loads the model from the mount and does not contact `huggingface.co` at startup, so a slow, blocked, or flaky Hub connection cannot stop the deployment. This applies to every cache-backed Guide, including P/D disaggregation, precise-prefix-cache-routing and tiered-prefix-cache. Keep the cache entry ready and complete, including the exact model revision, before you deploy; an offline model server cannot fall back to a download.

Hugging Face environment variables (`HF_*`, `HUGGING*`, `TRANSFORMERS_*`) are managed by the platform administrator. They cannot be set in the deployment editor's custom runtime overrides, and the planning and configuration APIs reject them; the platform derives them from the cluster's saved proxy, model cache and token settings.

## Download a model from Hugging Face

1. On the **Model cache** page, click **Download model**.
2. In **Download a model**, choose a **Cluster** and **Storage volume**.
3. Leave **Model source** set to **Hugging Face**.
4. Either type a **HuggingFace repo id** and **Revision** manually, or click **Browse Hugging Face Hub**.
5. If you opened **Browse HuggingFace Hub**, use **Search models…**, select a result from the left-hand list, then click **Use this model**.
6. Downloads use the **HuggingFace token saved with the cluster** (set in the cluster wizard); there is no token selection here. For a public model with no saved token, the download runs unauthenticated.
7. Click **Start download**.

## Download a model from Model Market

1. Click **Download model**.
2. In **Download a model**, set **Model source** to **Model Market**.
3. Click **Browse Model Market**.
4. In **Browse Model Market**, use **Search by model name, family, or repo...** and the category tabs under **Model categories** to find a model, then click its model card.
5. Back in **Download a model**, review the selected model details. If needed, click **Change model** to pick a different one.
6. Choose the **Cluster** and **Storage volume**.
7. Downloads use the **HuggingFace token saved with the cluster** (set in the cluster wizard) for private models.
8. Click **Start download**.

## Filter cached models

1. Use **Target cluster** to limit the page to one cluster, or leave it on **All clusters**.
2. In **Model cache storage**, click a storage card to filter the list to that volume.
3. Use **Search by model** to narrow the **Cached models** list.
4. Use the type tabs such as **All** and any model-type tabs shown by the page.
5. Use **Rows per page** and the pagination controls to move through longer result sets.

## View download logs

1. On a model card, click the action with the tooltip **View logs**.
2. In **Download logs**, choose a node from the dropdown if more than one node is listed.
3. Click the button titled **Refresh logs** if you want an immediate refresh. The modal also refreshes automatically while it is open.
4. Read the log output and the per-node status chips shown above it.

## Retry a failed download

1. Find a model card that shows a failed state.
2. Click the action with the tooltip **Retry download**.
3. Watch for the page notice **Retry started** and monitor the card again from **Progress** or **View logs**.

## Sync cached models to new nodes

1. If the page shows the header action **Sync new nodes (...)**, click it to start syncing every cached model that still needs to be copied to new nodes.
2. To sync only one model, find a card that says new nodes need the model and click the action with the tooltip **Sync new nodes**.
3. Watch for the notice **Sync started for new nodes** or **Nothing to sync — all models are up to date**.

## Delete a cached model

1. On the model card you want to remove, click the action with the tooltip **Delete cached model**.
2. In **Delete cached model**, review the warning about the exact cache path that will be removed.
3. Click **Delete cached model** to start the removal.
