---
title: Scheduler
description: How Lens decides where a deployment runs and which provider answers each inference request.
---

Lens has two distinct "scheduling" decisions, at two different points in
time: where to run a workload (deployment planning) and which running
backend answers a given request (Model Service selection policy).

## Deployment placement (agentic, workload-guided planning)

When you deploy a model from [Model market](/user-guide/model-market) or
[Deployments](/user-guide/deployments), you can describe the target workload
(traffic shape, latency/throughput goals) instead of hand-picking a cluster
and resource shape. The agentic planner combines that description with
retrieved evidence (prior runs, known-good configurations for similar
models/hardware) to propose a cluster, resource request and inference-engine
configuration, which you review and approve before it's applied. See the
[Architecture overview](/architecture) for the
full design.

This decision happens **once**, at deployment time — it is not re-evaluated
per request.

## Request routing (Model Service selection policy)

Once one or more cluster deployments are published as providers for a
[model service](/user-guide/model-services), every inference request to that
service is routed to exactly one provider by the group's **selection
policy**:

| Policy | Behavior |
| --- | --- |
| `random` | Uniformly random choice among healthy, enabled providers. |
| `round_robin` | Cycles through healthy, enabled providers in order. |

Only admins can change which policy a model service uses; maintainers can
still adjust a provider's parameters under whichever policy is currently
set (for example a future `weighted` policy's per-provider weight) for
providers in clusters they manage. Unhealthy or user-disabled providers are
excluded from selection until a health probe marks them healthy again — see
[Model services](/user-guide/model-services).

This decision happens **per request**, in the cluster data plane
(Gateway → HTTPRoute → InferencePool/EPP) — the Lens control plane is not on
this path.
